## Agent architecture

This repo has a Claude Code agent team in `.claude/` (generated by the `init-agents` skill). The **main session orchestrates**; specialized subagents do scoped work. Subagents can't spawn subagents — only the main session dispatches.

**Agents** (`.claude/agents/`):
- `explorer` — read-only codebase mapping (where/how things live).
- `planner` — read-only, file-level implementation plans.
- `implementer` — writes code to an approved plan.
- `reviewer` — critical review of the diff (bugs/security).
- `tester` — runs `{{TEST_CMD}}` / `{{BUILD_CMD}}`, fixes failures.
{{ORCHESTRATOR_LINE}}

**Commands** (`.claude/commands/`): `/feature <goal>` · `/fix <bug>` · `/review [scope]` · `/triage <bug-report>`.

**Hooks** (`.claude/settings.json` → `.claude/hooks/`): format-on-edit (non-blocking){{GUARD_NOTE}}.

**Stack**: {{STACK_SUMMARY}} · build `{{BUILD_CMD}}` · test `{{TEST_CMD}}` · lint `{{LINT_CMD}}`.

Invoke an agent directly with `@explorer …`, or run a pipeline with `/feature …`. Subagent file edits load on session restart (or via `/agents`).

**Dispatch transparency:** whenever you dispatch sub-agents, end the reply with a **Dispatch report** — *Why this config* (which agents and why that depth), a table `Agent | Why popped | What it did | Result`, and *Skipped* (agents not used + why). If no agents were used, end with `_Handled directly — no agents dispatched._`
